# SOP-EP-001 · Deploying an endpoint management agent (Tanium Client example)

Install, register and verify an endpoint management agent so the platform can see and act on every machine. An endpoint without the agent is unmanaged, which is why missing agents show up as audit findings. The Tanium Client is the worked example; the planning, methods and checks apply to most agents.

**Family:** Endpoint agents · **Covers:** Tanium architecture and ports, the `tanium-init.dat` file, manual, silent, remote, enterprise (Intune Win32, ConfigMgr, GPO) and Tanium-native deployment, verification and rollback · **Does not cover:** building the Tanium Server or Zone Server, or client upgrades (done from Tanium Client Management after install).

## How it fits together

![The Tanium Console talks to the server on HTTPS 443; clients in one subnet form a linear peer chain whose two ends talk to the server or an optional Zone Server on TCP 17472; every install stages SetupClient.exe with tanium-init.dat, installs, starts the service, registers and is verified](diagrams/sop-ep-001-1.svg)

Clients on the same subnet pass questions and answers along a chain, so only the leader and backward leader talk to the server. If a host firewall blocks peering, clients still work but each talks to the server directly, raising load.

| Port | Direction | Purpose |
|---|---|---|
| TCP 17472 | Client → Server or Zone Server | Registration, questions, answers, packages. The essential port |
| TCP 17472 | Client ↔ client, same subnet | Peer chaining |
| TCP 443 | Operator browser → Server | Console; Tanium Cloud also uses 443 for some client traffic |

`tanium-init.dat`, generated by the Tanium administrator, carries the server name list, port and the server's trust key. The installer reads it from its own folder. Without it the install "succeeds", the service runs, and the client never registers: installed but invisible. Never reuse an init file from another environment. Ports and switches vary by client version; check the Tanium documentation for the version supplied.

| Method | Best for |
|---|---|
| A · Manual | One machine, learning |
| B · Silent CLI / PowerShell (`/S`) | Scripts, task sequences |
| C · Remote (PsExec, WinRM) | A handful of remote PCs; runs the Method B command |
| D · Intune Win32, ConfigMgr, GPO startup script | Managed fleets; prefer the platform that already manages the endpoint |
| E · Tanium client deployment | Unmanaged estates, M&A |

## Before you start

| Item | Requirement |
|---|---|
| Access | Local Administrators (dedicated or LAPS account); Intune Application Manager; ConfigMgr Application Author and Deployment Manager; GPO edit and OU link rights; a Tanium role to deploy clients. Activate roles just-in-time |
| Files | `SetupClient.exe` and `tanium-init.dat` from the endpoint tooling owner, version and SHA-256 recorded |
| Change | Change or service request listing the endpoints (for example `PC-LAB-0001`) |
| Network | Endpoint resolves and reaches the server on TCP 17472; host firewall allows 17472 inbound from the local subnet; SMB 445 or WinRM 5985 for remote installs |
| Endpoint | Clock synchronised with the domain; EDR or application control allows the Tanium publisher certificate; no broken previous install |
| Risk | Low; the install is reversible |

```powershell
$server = 'tanium.contoso.com'
Resolve-DnsName $server
Test-NetConnection $server -Port 17472 | Select ComputerName, RemoteAddress, TcpTestSucceeded
Get-Service -Name 'Tanium Client' -ErrorAction SilentlyContinue   # empty on a new install
w32tm /query /status | Select-String 'Source|Last Successful'
```

## Steps

### Manual and silent

1. **Obtain and stage.** Request both files from the tooling owner. Copy them together to `C:\Install\Tanium\` and compare `Get-FileHash -Algorithm SHA256` with the supplied values.
2. **Install.** Right-click `SetupClient.exe` › **Run as administrator**, accept defaults. Keep the init file in place throughout.
3. **Silent.** The installer is NSIS-based; `/S` (capital S) runs silently with the init file beside it. The base template `Install-TaniumClient.ps1` checks both files and hashes, installs with `-WorkingDirectory` set to the source folder, waits for the service, sets it Automatic, tests port 17472, writes JSON evidence named with the change reference, and removes the staged files.

```bat
cd /d C:\Install\Tanium
SetupClient.exe /S
sc query "Tanium Client"
```

4. **Notify.** Tell the tooling owner the install is done and ask them to confirm reporting.

### Remote

5. **PsExec.** Copy both files to `\\%PC%\C$\Install\Tanium\`, then `psexec \\%PC% -s -w C:\Install\Tanium C:\Install\Tanium\SetupClient.exe /S`. Many EDR products flag PsExec: tell security operations first, or use remoting.
6. **PowerShell remoting.** Open a session, copy the two files and the template with `Copy-Item -ToSession` (avoids the Kerberos second hop), run the template with `Invoke-Command`.

### Enterprise and Tanium-native

7. **Intune Win32.** Source folder with both files and `install.cmd` containing `"%~dp0SetupClient.exe" /S`, so it runs from the package folder. Package with `IntuneWinAppUtil.exe -c .\src -s install.cmd -o .\out`; **Apps › Windows › Add › Windows app (Win32)**. Uninstall `"%ProgramFiles(x86)%\Tanium\Tanium Client\uninst.exe" /S` (confirm the path), install behaviour System, detection on `TaniumClient.exe` or the service. Required to a device group.
8. **ConfigMgr.** Both files on the content share; **Software Library › Application Management › Applications › Create Application**, Script Installer `SetupClient.exe /S`, file detection, install for system whether or not a user is logged on. Deploy Required, monitor **Monitoring › Deployments**.
9. **GPO startup script.** An idempotent script that returns if the service exists, copies both files from a read-only share to a temp folder, installs with `/S` and cleans up. Link under **Computer Configuration › Policies › Windows Settings › Scripts › Startup**. GPO gives no reporting, so query for stragglers.
10. **Tanium client deployment.** Confirm the option with the Tanium administrator, provide targets and a deployment credential stored in the console's credential store, ensure SMB 445 and remote service management, run and review per-endpoint results. Remove the credential's rights or rotate it afterwards. Its discovery reports list machines with no client.

## Verify

| Check | Pass |
|---|---|
| `Get-Service 'Tanium Client'` | Running, Automatic |
| `Get-NetTCPConnection -RemotePort 17472` | Established connection to the server |
| `log0.txt` in the install folder | Registration lines, no repeated errors |
| `TaniumClient.exe config get ServerNameList` | Expected server (current clients) |
| Interact question filtered to the host | Answer returned |
| Client Management health view | Online, expected version, in the expected computer groups |

## Rollback

Run `uninst.exe /S` from the install folder or the platform's uninstall deployment, reboot if prompted, and ask the Tanium administrator to remove the endpoint record if it will not return. Never delete the install folder by hand while the service exists.

## Troubleshooting

Check the service, then the init file, then port 17472, then the client log; ask the Tanium administrator last.

| Symptom | Cause and fix |
|---|---|
| Service running, never registers | No init file, or one from another environment: uninstall, stage both files together, reinstall |
| `TcpTestSucceeded : False` on 17472 | Firewall, proxy or routing: request a rule from the endpoint subnet to the server or Zone Server |
| Key or certificate errors in the log | Wrong init file or clock skew: `w32tm /resync`, reinstall with the correct file |
| Two endpoints share one identity | Cloned after install: follow Tanium's imaging guidance and reset the clone's identity |
| Installer blocked | Application control or EDR: allow-list the Tanium publisher certificate |
| Silent install does nothing | Not elevated or wrong working directory: use `-WorkingDirectory` or `%~dp0` |
